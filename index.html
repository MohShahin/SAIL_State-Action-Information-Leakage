SAIL: State→Action Information Leakage

The severity score a sepsis RL policy learns from already encodes the treatment it's about to recommend — closing a circular loop between action and state that undermines the premise the whole framework rests on.

The core mechanics

02 / proven mechanisms
MECHANISM 01

State → action confounding

The cardiovascular SOFA subscore is scored directly from vasopressor dose, not only blood pressure. Once a dose threshold is crossed, the score stops responding to physiology at all.

  • → Provable: two opposite MAP values, identical dose, identical score
  • → Removing the subscore alone isn't enough — the total reconstructs it by subtraction

MECHANISM 02

Overlapping temporal windows

Aggregation windows built to summarize "the current state" routinely overlap periods when treatment was already running — contaminating a supposedly pre-decision snapshot with treatment history.

  • → Provably nonzero at the limits; not simply monotonic in window length in between
  • → Verified twice, corrected once after a real extraction bug was found and fixed

Reproducibility & data governance

04 / open pipeline

Every extraction query is public. Every result figure has been independently re-derived and reproduced across five or more separate pipeline runs — including two real extraction bugs found, diagnosed, and fixed in the open.

  • 01Queries are public. Full BigQuery SQL for cohort, vitals/labs, and dose extraction.
  • 02Patient data is not. MIMIC-IV is credentialed-access; row-level output is never published — see governance policy.
  • 03History is unfiltered. Bugs, dead ends, and corrections are documented, not hidden.

queries/01_cohort.sql 
-- adult, first-ICU-stay, Sepsis-3-qualifying,
-- vasopressor-exposed ICU stays
WITH ranked_icu AS (
  SELECT
    ie.subject_id, ie.hadm_id, ie.stay_id,
    ROW_NUMBER() OVER (
      PARTITION BY ie.subject_id
      ORDER BY ie.intime
    ) AS rn
  FROM `physionet-data.mimiciv_3_1_icu.icustays` ie
  JOIN `physionet-data.mimiciv_3_1_hosp.patients` p
    USING(subject_id)
  WHERE p.anchor_age >= 18
)
SELECT f.* FROM ranked_icu f
WHERE f.rn = 1;

-- verified result: 11,354 stays, exact match
-- across five independent runs
