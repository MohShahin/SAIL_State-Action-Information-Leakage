We gave a model a question and accidentally also gave it the answer.

This is that story — and it's not about a bad model. It's about a widely-used clinical score that was never designed to be a machine-learning feature in the first place. Three acts, all built from real, already-verified numbers — nothing on this page is fabricated.

One synthetic patient, three synchronized views: a causal graph that lights up when treatment information flows into the state, a state vector that flips cells between clean and treatment-confounded, and a predictability gauge that moves with it — all three driven by the same mechanism proven in Act 2 below, not a staged animation.

Act 2 — The whole finding in one plot

Six state designs, tested on the same task: predict the next vasopressor decision from the current state. The x-axis groups them by physiological purity — does the state still contain a raw, treatment-derived SOFA feature that fails Theorem 1's non-identifiability check? The y-axis is each variant's actual, already-verified action-recoverability AUROC — no new computation here, same numbers as the Evidence page.

Low purity — contains a raw treatment-derived SOFA feature High purity — SOFA features fixed, no raw dose term Highest purity — zero treatment-derived features of any kind

F is the point that matters here. It sits in the same purity bucket as D — same construction logic, no raw dose feature either — yet it has the highest action-recoverability AUROC of all six variants, above even the untouched full state (A). Purity and low recoverability visibly are not the same axis: D and E's designer might reasonably expect "no raw treatment feature" to mean "hard to predict the next action from," and for D and E that expectation holds — but F shows it isn't a guarantee. Two purely temporal history features (duration on vasopressor, time since the last dose-tier change) reconstruct the next action better than physiology does, without reintroducing a single raw SOFA-embedded dose term. Full write-up: Evidence, Experiment 8.

Act 3 — What we don't know yet
H3 — open question

Everything in Act 2 is proven or directly measured. One question isn't settled: does the AUROC gap in Experiment 2 actually reflect the mechanisms proven here (Theorems 1–2), or is it substantially explained by ordinary treatment persistence — vasopressor courses just don't change from one decision point to the next very often, independent of any SOFA-construction quirk? The pre-registered test for this is a paired cluster bootstrap on the offset-decay curve's AUROC(0)−AUROC(8) difference — resampling patients once per iteration and computing both AUROCs on that same resample, specifically because the two AUROCs are computed on the same, correlated patients; a marginal comparison or a point-estimate threshold isn't valid here. The negative-control battery has run and produced a real decay curve (0.874 → 0.703) — but that run bootstrapped each offset independently and saved only the aggregate AUROC and CI per offset, not the per-patient predictions a joint resample needs. Closing this is a small, well-scoped next step — save predictions across offsets, one new paired-bootstrap analysis pass — not an open-ended gap. See current status.

Act 2's Variant F result (Experiment 8) is corroborating evidence for the persistence explanation, not a resolution of H3: it shows that purely temporal treatment-history features are highly predictive on their own, consistent with persistence being a large effect in this cohort — but it wasn't designed as a test of the offset-decay curve specifically, and doesn't substitute for that pre-registered instrument. We proved two mechanisms. We don't yet know how much of the practical predictability gap they explain versus ordinary persistence. That's the actual open question this project is built to answer next.

Deliberately not built: dual RL agents, live Q-value comparisons, or any policy-level visualization. No RL policy has been trained anywhere in this project — Experiment 8 used classifiers to test action-recoverability and mortality-predictive validity, not a trained policy. A demo element implying otherwise would misrepresent the project's actual state, regardless of how compelling it would look. Those become buildable once a policy-sensitivity study (the deferred Experiment 4) actually runs.
