Why Experiment 2's gap is the strongest single result

The AUROC gap (0.900 → 0.791) survived a 15× difference in underlying vasopressor-dose row counts almost untouched — 0.109 verified vs. ≈0.108 in the original, inflated-data run. A result that's this stable despite a large upstream data bug is strong evidence it reflects something structural (Theorems 1–2), not an artifact of how the data was extracted.

The three bugs, found and fixed in the open

Bug 1 — WRITE_APPEND
The cohort table's BigQuery load had no write_disposition. A re-run against an already-populated table silently duplicated rows (~15x). Confirmed twice — by code inspection, and by recovering the original buggy Colab run and reproducing its exact inflated numbers.
Bug 2 — schema autodetect
BigQuery's schema autodetection mapped a timestamp column to the wrong type, breaking downstream joins. Fixed with an explicit schema.
Bug 3 — sum vs. union
The window-overlap calculation summed overlapping intervals instead of taking their union, double-counting patients on simultaneous multi-drug vasopressor therapy (34.8% of the cohort).

Full diagnostic trail — including the false starts — in ROADMAP.md.

A scope note: this evidence is task-specific

Everything on this page evaluates a feature's relationship to next-action prediction specifically. That's a deliberate scope, not an oversight — the same feature's status can differ entirely for a different task. A cardiovascular-subscore value that's treatment-confounded for predicting the next vasopressor action may be exactly the right feature for predicting mortality: mortality prediction doesn't carry the "was this information available before the decision" constraint that action-prediction does. None of the figures above should be read as "this feature is bad" in general — only "this feature's value for predicting the next action is inflated by treatment history, by this much." See Terminology for the full distinction this depends on.

Limitation: sanitization has a clinical-validity cost

Variant D's fix (recompute the total from a MAP-only cardiovascular proxy) removes the treatment-confounding this project measures — but it isn't free. The MAP-only branch of the scoring rule (score_map = 1 if MAP < 70 else 0) is a two-level signal that cannot distinguish a patient who is healthy and untreated from one who is successfully treated and still critically ill — the second patient's MAP looks the same as the first's once vasopressors have done their job.

Concrete example, computed from the actual scoring function: a patient on norepinephrine 0.15 mcg/kg/min with MAP 74 (successfully restored to normal by the drug they're actively receiving).

4

0
Variant D cardiovascular SOFA — incorrectly reads as healthy, since MAP alone is now normal

This is a genuine tradeoff, not an argument that sanitization is the wrong approach: predictive purity (Variant D/E's lower action-recoverability) is bought at a real cost in clinical validity (losing the "needed treatment to reach this value" signal). Whether that cost is acceptable is task-dependent (see the scope note above) — and is exactly what motivates disentangling severity from treatment history as two separate, explicit terms, rather than collapsing them into one composite score either way.

Testing that concern quantitatively: it doesn't hold at the cohort level

The concrete example above is real, but does it add up to variant D/E being meaningfully worse at predicting mortality across the whole cohort? Trained the same way as Experiment 2 (logistic regression / random forest / gradient boosting, clustered bootstrap CIs) but predicting in-hospital mortality from the state at a single fixed 24h decision point — matching SOFA's own original validation convention — rather than the next action at every timestep:

The individual-patient failure mode is still mathematically real; it just doesn't appear to aggregate into a large mortality-AUROC loss.
